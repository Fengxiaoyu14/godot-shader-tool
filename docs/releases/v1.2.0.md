## Fixes and features

- Read and write Godot 3.5 and 3.6 binary format-v3 resources. Writes preserve the original engine version, format version, compression mode, and non-code metadata.
- Follow indexed and legacy inline external Shader references instead of returning a misleading `SHADER_NOT_FOUND`.
- Resolve `res://` from the nearest ancestor `project.godot`, or use `project_root`. Use `shader_path` for a separately supplied or renamed dependency. All three tools accept these options with file input.
- Read, validate, and write standalone binary Shader resources, text Shader `.tres` files, and `.shader`/`.gdshader` source.
- External writes modify the actual shared Shader file and preserve the material. Results include `written_path`, `source`, and `shared_shader`. All materials using that shared Shader see the change.
- Preserve decoded source exactly, including Unicode and LF/CRLF. Text `.tres` writes preserve every character outside the root `code` String token, including BOM, comments, and metadata.
- Require official shader validation before writing and after actual temporary-file read-back. Check non-code content and concurrent changes to both material and Shader before safe replacement.
- Report missing project roots, missing/unreadable dependencies, wrong resource types, malformed text, and invalid UTF-8 with actionable file context.

## Usage

```text
godot-shader-read({
  path: "D:/work/project/materials/example.material",
  project_root: "D:/work/project"
})

godot-shader-write({
  path: "D:/work/project/materials/example.material",
  shader_code: "shader_type spatial;\nvoid fragment() { ALBEDO = vec3(0.5); }",
  project_root: "D:/work/project"
})
```

For a detached dependency, replace `project_root` with `shader_path: "D:/samples/uploaded-shader.tres"`.

## Verification and limits

- Source tests cover both binary versions and containers, embedded/external/standalone reads and writes, root discovery and overrides, text escaping, unchanged non-code data, invalid shader rejection, concurrent edits, and installed tool wrappers.
- A private Godot 3.6 material plus its real external `.tres` were tested locally without publishing their contents.
- A private Godot 3.5 external-reference material was parsed successfully. Its original referenced `.tres` was not provided; write-through was tested with an explicit dependency override, alongside synthetic 3.5 embedded and external fixtures.
- Binary compatibility is explicitly limited to Godot 3.5/3.6, format v3. The bundled shader compiler remains **Godot 3.6 GLES3**; this does not claim a separate Godot 3.5 compiler.
- Text ShaderMaterial files, recursive material references, resource creation, and Godot 4 binary/text resource formats remain unsupported.
- The legacy synchronous `readGodot36Shader(bytes)` name is retained. Byte-only APIs do not resolve files; use `readGodotShaderFile` / `writeGodotShaderFile` for external references.

## Install / upgrade

Download the Windows x64 or Linux x64 ZIP below, then copy its complete `tools` directory to `~/.config/opencode/tools` and restart OpenCode. Do not copy only the tool entry points; new runtime modules must be installed together. Packages exclude source tests and all private assets.

The release workflow runs tests on Linux and Windows before publishing both platform ZIPs and `SHA256SUMS`.
