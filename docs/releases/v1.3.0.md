# v1.3.0 — 补丁写入、批量计划与 Shader 检索

本版本补齐批量 Shader 优化所需的读、搜、改、验能力。补丁直接作用于工具内部读取的源代码，无需让调用方转录完整 Shader。

## 新增功能

- **补丁写入 `godot-shader-write-patch`**：支持字面量查找替换和带原文校验的行删除。每条操作必须声明 `expect`；任一断言失败，整个文件零变更。保留未修改部分的空白、Unicode 和 LF/CRLF。
- **批量写入 `godot-shader-write-plan`**：读取 JSON plan，逐文件执行官方前后验证、临时文件回读和安全替换。单文件失败不阻断后续文件，返回逐文件结果、错误、hash 和 diff。一次工具审批覆盖整个 plan。
- **Shader 搜索 `godot-shader-search`**：复用现有 reader 检索 material 和独立 Shader，支持字面量、逐行正则及分页，返回路径、匹配行、行号和代码 hash。
- **内容 hash**：read 返回解码后 Shader 源码的 SHA-256，可识别不同材质中的完全相同代码副本。
- **渐进读取**：`metadata_only` 返回长度、hash、uniform 清单和函数签名；`start_line` / `end_line` 按需读取代码段。声明索引是词法导航信息，不替代语法验证。
- **写入 diff 与预演**：完整写入、补丁和批量结果提供 unified diff；`dry_run` 完成验证但不替换原文件，`expected_hash` 防止基于过期源码写入。

## 使用示例

```text
godot-shader-write-patch({
  path: "materials/car.material",
  ops: [{find: "vec4 light;", replace: "vec4 light = vec4(0.);", expect: 1}]
})

godot-shader-write-plan({plan_path: "plans/fresnel.json", dry_run: true})
godot-shader-write-plan({plan_path: "plans/fresnel.json"})

godot-shader-read({path: "materials/car.material", metadata_only: true})
godot-shader-search({pattern: "fresnel", project_root: "."})
```

Plan 内容为 `[{"path":"../materials/car.material","ops":[...]}]`。其中的路径相对于 plan 所在目录，而非调用时的工作目录。

## 安全边界与兼容性

- 操作按顺序作用于当前中间源码。删除行使用 1-based 闭区间，并要求 `expected_text` 与完整原文（含换行）一致。
- 批量执行前解析实际写入目标并固定源码 hash；多个条目指向同一个共享外部 Shader 时，拒绝全部冲突条目，避免重复修改。独立的内嵌副本逐文件处理。
- 批量采用逐文件事务；失败文件保留原始内容，先前成功的文件不整体回滚。并发修改及无法确认的系统替换失败会单独标记，避免误报“已回滚”。
- 明确 Godot 序列化末尾 NUL 由 codec 消费和重建，不属于源码、hash 或 diff；不新增空白或换行归一化。
- `godot_version` / `renderer` 预留验证器选择入口，实际仅支持 **Godot 3.6 GLES3**，其他组合明确报错。
- 保持 Godot 3.5/3.6 binary format-v3 的资源读写范围；不新增 VisualShader、Godot 4.x、文本 ShaderMaterial 或从零创建资源支持。
- 验证器检查语法与语义，不证明视觉等价或 GPU 性能收益。

## 升级

使用对应平台的安装包，将完整 `tools` 目录复制到 `~/.config/opencode/tools` 并重启 OpenCode。不要只替换入口文件。

将 `godot-shader-search` 配为 `allow`，将 `godot-shader-write-patch` 和 `godot-shader-write-plan` 配为 `ask`；参见安装包中的 `opencode.example.json`。包内仅含运行时和对应平台的 validator，不含测试或私有素材。
